Locks and Condition Variables¶

# Global Variables
size_t MIN_FRIENDS = 2  # Minimum number of friends before we have courage
size_t Friends     = 0  # Current number of friends brave enough

Mutex Lock
Cond  Dancing

# Threads

def thread_you_dance():
    mutex_lock(Lock)
    while Friends < MIN_FRIENDS:
        cond_wait(Dancing, Lock)
    mutex_unlock(Lock)

    dance()

def thread_friend_dance():
    mutex_lock(Lock)
    Friends++
    cond_signal(Dancing)
    mutex_unlock(Lock)

    dance()

Bug: Atomicity Violation¶

An atomicity violation occurs when we have a code region that assumes its execution is atomic, but it is not actually enforced.

UNLOCK()

UNLOCK()

Bug: Deadlock¶

A deadlock occurs when each thread is waiting for another to give up a resource and none can run. Usually this is because there is a cycle in the graph of dependencies.

Thread 1 Thread 2 
Lock(Mask)
Lock(Sanitizer)

Lock(Sanitizer)
Lock(Mask)

Bug: Livelock¶

Livelock occurs when multiple threads are actively attempting to acquire resources, but cannot make progress.

Thread 1 Thread 2 
while True:
    Lock(Mask)
    # Check if other resource
    # is already locked
    if Locked(Sanitizer):
        Unlock(Mask)
        continue
    Lock(Sanitizer)
    ...
    Unlock(Sanitizer)
    Unlock(Mask)

while True:
    Lock(Sanitizer)
    # Check if other resource
    # is already locked
    if Locked(Mask):
        Unlock(Sanitizer)
        continue
    Lock(Mask)
    ...
    Unlock(Mask)
    Unlock(Sanitizer)

Bug: Dining Philosophers¶

There are five philosophers eating dinner...

  • There are only five forks.

  • To eat, each person needs a left and right fork.

Need to ensure no deadlock and no one starves.

def philosopher(p):
    while True:
        think(p)
        get_forks(p)    # Deadlock!!!
        eat(p)
        put_forks(p)

def get_forks(p):
    sem_wait(forks[left(p)])
    sem_wait(forks[right(p)])

def put_forks(p):
    sem_post(forks[left(p)])
    sem_post(forks[right(p)])

Bug: Deadlock Conditions¶

Mutual Execution


Threads claim exclusive control of resources.


Don't share, add more chopsticks

No Pre-emption


Resources cannot be forcibly removed from threads holding them.


Run-time/scheduler that pre-empts threads (take away resources).

Hold-and-Wait


Threads hold resources while waiting for additional resources.


Try, put down, retry... could lead to livelock.

Circular Wait


There exists a circular chain of threads such that each thread holds one or more resources needed by another.


Provide an ordering: odds/evens, token ring (bottle of wine), one person grabs right then left.
