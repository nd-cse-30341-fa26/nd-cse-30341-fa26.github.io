Memory API: Trivia¶

Allocation¶

How do we allocate an array of 1,000,000 ints?

int *a = malloc(1_000_000 * sizeof(int));
int *a = calloc(1_000_000, sizeof(int));

Deallocation¶

How do we deallocate that array of ints?

free(a);

Common Error A¶

What is the memory error in the following code?

char *buffer;
fgets(buffer, BUFSIZ, stdin);
Forgot to allocate memory, so we segfault. 
// Solution: allocate space on the stack
char buffer[BUFSIZ];
fgets(buffer, BUFSIZ, stdin);

Common Error B¶

What is the memory error in the following code?

char *src = "Smile like you mean it";
char *dst = malloc(strlen(src));

strcpy(dst, src);
Did not allocate enough memory, so buffer overflow. 
// Solution: use strdup
char *src = "Smile like you mean it";
char *dst = strdup(src);

Shout out to Cybersecurity club.

Common Error C¶

What is the memory error in the following code?

char *s = malloc(100*sizeof(char));

puts(s);
Did not initialize memory, so uninitialized read. 
// Solution: initialize memory
char *s = calloc(100, sizeof(char));

puts(s);

Common Error D¶

What is the memory error in the following code?

for (int i = 1; i < argc; i++) {
    char *s = strdup(argv[i]);
    process(s);
}
Forgot to free memory, so memory leak. 
// Solution: free
for (int i = 1; i < argc; i++) {
    char *s = strdup(argv[i]);
    process(s);
    free(s);
}

Common Error E¶

What is the memory error in the following code?

for (int i = 1; i < argc; i++) {
    char *s = strdup(argv[i]);
    process(s); free(s); puts(s);
}
Freed before we are done, so dangling pointer, which can lead to a use-after-free.

Common Error F¶

What is the memory error in the following code?

for (int i = 1; i < argc; i++) {
    char *s = strdup(argv[i]);
    if (check(s)) { free(s); }
    free(s);
}
Try to free something more than once, so double free.

Common Error G¶

What is the memory error in the following code?

for (int i = 1; i < argc; i++) {
    char *s = argv[i];
    process(s);
    free(s);
}
Try to free something that wasn't dynamically allocated, so invalid free.

Challenge: External Fragmentation¶

Because memory is divided into blocks, we may have non-contiguous free space.

Mechanisms: Splitting & Coalescing¶

Splitting¶

Instead of always asking for more memory, we can reuse a block of free space.


Helps reduce internal fragmentation.

Coalescing¶

When we free memory, we can check if there are contiguous free blocks and coalesce or merge them.


Helps reduce external fragmentation.

Free List: Overview¶

To track all of the block allocations, we can use a free list, which is a linked list of all the space reservations (can contain both active and free blocks or just the free blocks).

  • Operating system must track system memory allocations.

  • Individual processes must also keep track of heap allocations.

  • Must be wary of fragmentation.

Free List: Block Structure¶

We can view memory as one large array. To keep track of allocated blocks, we embed a block header in front of each block:

typedef struct block block;

struct block {
    size_t  size; /* Size of data allocation */
    block * next; /* Pointer to next block */
    bool    free; /* Whether or not block is free */
};

Bookshelf Analogy:

Each book has a index card with information about the book itself and the location of the next book.

Free List: Allocation¶

Whenever we get a request for memory, we must reserve a block:

If a previously allocated block is free and large enough, we can use that one. Otherwise, we need to allocate a new block.

Whenever we release memory, we simply mark that block as free.

Free List: First Fit¶

When searching for a free block, we can:

Find the first block that is big enough and return that block to the user.

To allocate a 12 byte block, we would use Block A (fast, but possibly sub-optimal).

Free List: Next Fit¶

When searching for a free block, we can:

Keep track of the last block we search, and perform First Fit from there.

To allocate a 12 byte block, if we last searched Block A, we would use Block B (fast, better distribution, but still sub-optimal).

Free List: Best Fit¶

When searching for a free block, we can:

Search all free blocks for the best possible fit.

To allocate a 12 byte block, we would use Block C (optimal, but slow and prone to many holes).

Free List: Worst Fit¶

When searching for a free block, we can:

Search all free blocks for the worst possible fit (largest fit).

To allocate a 12 byte block, we would use Block B (non-optimal but avoids having many small gaps, slow).
